## 1. EXECUTIVE SUMMARY
Tài liệu này đặc tả toàn bộ luồng tự động hóa Khôi phục & Bảo trì Tài khoản Microsoft (bao gồm gửi OTP, lấy session, tạo recovery code, đổi mật khẩu, tắt thông báo, đổi alias). 

Toàn bộ API và kỹ thuật scraping trong tài liệu này **đã được xác minh thực tế 100% bằng lệnh `curl`**. Các tài liệu audit cũ (đánh giá regex HTML bị hỏng) là **SAI**. Microsoft vẫn giữ nguyên cấu trúc HTML cũ, nhưng bổ sung cơ chế **Unicode Escape** và **Rate Limit (State 201/206)**, khiến code cũ dễ dàng bị crash nếu không xử lý đúng.

## 2. ARCHITECTURE & TECH STACK
*   **HTTP Client:** Ktor Client (Engine: OkHttp). Bắt buộc cấu hình `CookieJar` (AcceptAllCookiesStorage) cho từng session.
*   **JSON Parser:** `kotlinx.serialization`. (Tự động decode Unicode escape).
*   **HTML Parser:** `Jsoup`. (Chỉ dùng để tìm thẻ `<input>`, không dùng regex DOM).
*   **Concurrency:** Kotlin Coroutines (Suspend functions).
*   **Discord Layer:** Kord (Giao tiếp qua slash command/button, sử dụng `deferPublicUpdate` để tránh timeout 3s).

## 3. CRITICAL PITFALLS & WARNINGS (BẮT BUỘC ĐỌC)

### 3.1. Unicode Escape (Bug chí mạng của code cũ)
*   **Hiện tượng:** Các token như `encryptedNetId`, `apiCanary`, `sRecoveryToken` nằm trong HTML/JSON thường bị Microsoft escape (VD: `\u002b` thay vì `+`, `\u003a` thay vì `:`).
*   **Hậu quả:** Nếu gửi nguyên chuỗi `\u002b` lên API, Microsoft sẽ trả về **HTTP 500 Internal Server Error**.
*   **Cách xử lý:** 
    *   **Kotlin:** Dùng `kotlinx.serialization` parse thẳng JSON blob. Nó sẽ tự decode `\uXXXX`.
    *   **Bash:** Dùng `python3 -c "import codecs; print(codecs.decode(..., 'unicode_escape'))"`.

### 3.2. PPFT Escaped Quote (Bug extractor)
*   **Hiện tượng:** `PPFT` nằm trong `var ServerData = ({...,"sFTAg":"<input type=\"hidden\" name=\"PPFT\" value=\"...\">",...});`
*   **Cách xử lý:** Phải parse JSON `ServerData` trước, lấy field `sFTAg`, sau đó mới dùng regex `value=\\?"([^"\\]+)` để bóc tách PPFT. Không dùng regex quét toàn bộ HTML.

### 3.3. Rate Limits & Soft Errors (State 201/206)
*   **Hiện tượng:** API `GetOneTimeCode.srf` trả về `State: 201` (gửi quá nhanh) hoặc `State: 206` (proof tạm khóa).
*   **Cách xử lý:** ĐÂY KHÔNG PHẢI LỖI CHẾT. Miễn là response vẫn trả về `FlowToken` (khác null), bạn phải **bỏ qua State** và tiếp tục hiển thị form nhập OTP cho user. Nếu throw Exception ở đây, bot sẽ chết oan.

### 3.4. Dynamic UAID
*   Tuyệt đối không hardcode `uaid` (như `9b699236...`). Phải generate ngẫu nhiên 32 ký tự hex cho mỗi session để tránh bị Microsoft Risk Engine gắn cờ.

## 4. DETAILED WORKFLOW & API CONTRACTS

### Stage 1: Discovery & Credential Check
*   **GET** `https://login.live.com/login.srf`
    *   **Headers:** `User-Agent` (Chrome), `Accept: text/html...`
    *   **Response:** HTTP 200 HTML. Lưu Cookies (`uaid`, `MSPOK`, `MSPRequ`).
    *   **Extract:** `PPFT` (từ `ServerData.sFTAg`).
*   **POST** `https://login.live.com/GetCredentialType.srf`
    *   **Headers:** `Content-Type: application/json`
    *   **Payload:** `{"username": "<email>", "flowToken": "<PPFT>", "isUcuxLoginForm": true, "checkPhones": true}`
    *   **Response JSON:**
        *   `IfExistsResult`: `0` (Tồn tại), `1` (Không tồn tại), `5` (Bị throttle/captcha).
        *   `Credentials.OtcLoginEligibleProofs[0].data`: `<proofId>`
        *   `Credentials.OtcLoginEligibleProofs[0].type`: `1` (Email), `2` (SMS/Phone).

### Stage 2: OTP Dispatch & Session Establishment
*   **POST** `https://login.live.com/GetOneTimeCode.srf`
    *   **Headers:** `Content-Type: application/x-www-form-urlencoded`
    *   **Payload (Form):** `login=<email>`, `flowtoken=<PPFT>`, `purpose=eOTT_OtcLogin`, `channel=Email` (hoặc `SMS` nếu type=2), `AltEmailE=<proofId>`.
    *   **Response JSON:** `{ "State": 201, "FlowToken": "<new_flow_token>" }`
*   **POST** `https://login.live.com/ppsecure/post.srf`
    *   **Headers:** `Content-Type: application/x-www-form-urlencoded`
    *   **Payload (Form):** `login=<email>`, `loginfmt=<email>`, `type=27`, `SentProofIDE=<proofId>`, `otc=<OTP_code>`, `PPFT=<new_flow_token>`, `LoginOptions=3`.
    *   **Response:** HTTP 200/302. Trích xuất cookie `__Host-MSAAUTH` từ header `Set-Cookie`.

### Stage 3: Session Polish (AMRP)
*   **GET** `https://login.live.com/login.srf?wa=wsignin1.0&rpsnv=21&rver=7.5.2156.0&wp=SA_20MIN&wreply=https://account.live.com/proofs/Add?apt=2&uaid=<uaid>&lc=1033&id=38936&mkt=en-US`
    *   **Headers:** `Cookie: __Host-MSAAUTH=<session>`
    *   **Response HTML:** Lấy token `t` tại `<input name="t" value="<token_t>">`.
*   **POST** `https://account.live.com/proofs/Add?apt=2&wa=wsignin1.0`
    *   **Payload (Form):** `t=<token_t>`
    *   **Response:** HTTP 302. Trích xuất cookie `AMRPSSecAuth` và `amsc`.

### Stage 4: Proofs Enumeration
*   **GET** `https://account.live.com/proofs/manage/additional`
    *   **Headers:** `Cookie: AMRPSSecAuth=...; amsc=...`
    *   **Response HTML:** ~230KB. Tìm biến `var t0 = {...}`.
    *   **Extract:** 
        *   `WLXAccount.manageProofs.encryptedNetId` (Decode Unicode).
        *   `WLXAccount.manageProofs.apiCanary` (Decode Unicode).
        *   Mảng `emailProofs` và `smsProofs` (để tắt thông báo).

### Stage 5: Recovery Code Generation
*   **POST** `https://account.live.com/API/Proofs/GenerateRecoveryCode`
    *   **Headers:** `canary: <apiCanary>`, `Content-Type: application/json`, `x-ms-apiVersion: 2`
    *   **Payload JSON:** `{"encryptedNetId": "<encryptedNetId>"}`
    *   **Response JSON:** `{"recoveryCode": "XXXXX-XXXXX-XXXXX-XXXXX-XXXXX", "apiCanary": "<new_canary>"}`

### Stage 6: Password Reset
*   **GET** `https://account.live.com/ResetPassword.aspx?wreply=https://login.live.com/oauth20_authorize.srf&mn=<email>`
    *   **Response HTML:** Tìm `var ServerData = {...}`.
    *   **Extract:** `sRecoveryToken` (562 chars) và `apiCanary` (Decode Unicode).
*   **POST** `https://account.live.com/API/Recovery/VerifyRecoveryCode`
    *   **Headers:** `canary: <apiCanary>`, `Content-Type: application/json`
    *   **Payload JSON:** `{"publicKey": "2CBB3761027476727BDDBC9DE02870BE01ED793A", "recoveryCode": "<code>", "code": "<code>", "scid": 100103, "token": "<sRecoveryToken>", "uiflvr": 1001}`
    *   **Response JSON:** `{"token": "<verification_grant_token>", "apiCanary": "<new_canary>"}`
*   **POST** `https://account.live.com/API/Recovery/RecoverUser`
    *   **Headers:** `canary: <new_canary>`, `Content-Type: application/json`
    *   **Payload JSON:** `{"contactEmail": "<email>", "contactEpid": "", "password": "<new_password>", "passwordExpiryEnabled": 0, "publicKey": "2CBB...", "token": "<verification_grant_token>"}`
    *   **Response JSON:** `{"recoveryCode": "<new_recovery_code>", "enableTfa": true}`

### Stage 7: Notification Suppression
*   **POST** `https://account.live.com/API/Proofs/SetUserNotificationState`
    *   **Headers:** `canary: <apiCanary>`, `Content-Type: application/json`
    *   **Payload JSON:** `{"proofDetails": [{"name": "<displayProofId>", "notificationEnabled": false, "type": "Email"}], "uiflvr": 1001, "uaid": "<dynamic_hex>", "scid": 100109, "hpgid": 201030}`
    *   **Lưu ý:** Bắt buộc phải lặp qua toàn bộ proofs và gửi từng request tuần tự. Nếu 1 cái fail -> Dừng toàn bộ luồng (Fail-closed).

### Stage 8: Alias Rotation (Đổi Email)
*   **POST** `https://account.live.com/AddAssocId`
    *   **Payload (Form):** `canary=<canary>&PostOption=NONE&SingleDomain=outlook.com&AddAssocIdOptions=LIVE&AssociatedIdLive=<new_prefix>`
*   **POST** `https://account.live.com/API/MakePrimary`
    *   **Payload JSON:** `{"aliasName": "<new_email>", "emailChecked": true, "removeOldPrimary": false, "uiflvr": 1001, "uaid": "<hex>", "scid": 100115, "hpgid": 200650}`
*   **POST** `https://account.live.com/names/manage`
    *   **Payload (Form):** `canary=<canary>&action=RemoveAlias&aliasName=<old_email>&displayName=<old_email>`

### Stage 9: Cleanup & Revocation
*   **POST** `https://account.live.com/API/Proofs/DisableTfa`
*   **POST** `https://account.live.com/API/Proofs/DeleteDevices`
*   **POST** `https://account.live.com/API/Proofs/DeleteAppPassword`
*   **POST** `https://account.live.com/API/Proofs/RemovePasskey`
    *   **Payload JSON chung:** `{"uiflvr": 1001, "uaid": "<hex>", "scid": 100109, "hpgid": 201030}` (Riêng RemovePasskey cần thêm `passKeyId`).

## 5. ERROR HANDLING & RATE LIMITS
*   **GetOneTimeCode (`State 201/206`):** Bỏ qua, vẫn tiếp tục lấy `FlowToken` và chờ user nhập OTP.
*   **RecoverUser (`Error 6001`):** Tài khoản có 2FA bảo vệ, không thể reset pass tự động.
*   **RecoverUser (`Error 1218`):** Mật khẩu mới trùng mật khẩu cũ. Yêu cầu user nhập pass khác.
*   **MakePrimary (`Error 1282`):** Đã đạt giới hạn đổi alias trong tuần. Không thể đổi.
*   **Interaction Ack (Discord):** Tuyệt đối không gọi `event.acknowledge()` 2 lần. Nếu đã `deferPublicUpdate()`, khi báo lỗi phải dùng `event.editPublicUpdateResponse()`.

## 6. OUT OF SCOPE / BLOCKED BY MICROSOFT
1.  **2FA TOTP Setup (Authenticator App):** 
    *   Regex cũ `<span class="dirltr bold">` đã bị Microsoft xóa bỏ. Chưa có selector thay thế để scrape `secretKey`.
2.  **Minecraft Ownership Check (Stage 5 cũ):**
    *   OAuth Endpoint (`oauth20_authorize.srf?client_id=00000000402B5328`) bị Microsoft chặn bằng **Consent Interstitial** hoặc **Captcha (Arkose)** nếu account vừa reset password.
    *   **Giải pháp:** Không dùng scrape. Sử dụng thư viện **MSAL (Microsoft Authentication Library)** với Device Code Flow, hoặc lấy token thủ công từ Minecraft Launcher cache.
